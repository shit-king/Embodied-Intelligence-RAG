# v0.6 图注召回与裁剪

> 一句话：研报里的图常常**就是答案本身**（一张时间轴图胜过三段文字描述）。这一期让系统按问题语义召回最相关的图，把图从 PDF 页里**裁出来插进回答**——问"宇树机器人的发展历程"，回答下方直接附上那张「图6 宇树发展时间轴」。

## 为什么这一期重要

v0.5 解决的是"图表里的**数字**能被检索问答"（VL 转写成文本）。但用户真正想要的有时是**那张图本身**：发展历程、产业链图谱、专利结构图、产品矩阵——这些信息以视觉形式呈现时，一张图的信息密度和可读性远超文字转写。

而且 v0.5 只覆盖**无文字层的整扫描页**（`empty_pages`）。绝大多数券商研报的图是画在**有文字层的正常页**上的（图旁边就是可选中的正文），这些图从没被当作"图"提取过——既不可检索，也无法展示。这一期补上这块。

**触发这一期的真实 case**：问"宇树机器人的发展历程"，召回的 top10 全是文字页，回答只有文字。但库里其实有《具身智能产业深度研究(五)》p6 的「图6 宇树发展时间轴」——一张完美对应的图，却因为不在召回链路里而拿不到。

## 技术方案

```
离线：扫每页文字层「图N: 标题」图注 → 连续带定位图区(bbox) → figures.jsonl
在线：bge-m3 嵌入图注 → 按问题余弦召回(≥0.55) → /figure-image 按bbox裁剪渲染 → 回答内"相关图表"区
```

### 1. 为什么走"图注召回"，而不是图像检索

图注（"图6: 宇树科技2016年成立于杭州…"）是**报告作者亲手写的、对图内容的高质量摘要**，且是干净的文字——直接复用现有 bge-m3 嵌入即可语义匹配，零额外模型、零 VL 成本。相比之下 CLIP 类图像向量要另起一套编码+索引，且"以文搜图"的跨模态对齐质量未必比图注文本检索更好。**先用最便宜可靠的信号（图注）打通闭环，是更划算的工程顺序。**

实测：1960 张图的图注嵌入成 `figures.npy`（一次性），查询时 query 向量与 1960×1024 矩阵做一次内积，毫秒级，与主检索并行无感。

### 2. 裁剪：连续带 + 宁缺毋滥

最难的不是找图注，是**把图从页面里干净裁出来**。踩的坑：

- **图注位置不统一**：海通国际是"注在图上方"，国泰君安是"注在图下方"。纯按位置裁必翻车（按错方向会裁出整片空白）。
  → 解法：以图注为锚，**比较上下两侧的"墨水量"**（raster 图 + 矢量绘制块 + 图内短文本标签的面积），往图形多的一侧扩展。
- **图与正文的边界**：图区会一直扩到最近的**正文段落/页眉脚/另一图注/"资料来源"行**为止；并把紧贴图底的来源行纳进来——裁出来的图自带标题和出处，自解释。其中"资料来源"行必须当作边界，否则向上找边界时会越过它、把上一张图也并进来（实测翻车点）。
- **双栏图网格**：研报常把 4 张图排成 2×2 网格，图注在底部。早期按整页宽裁会把左右两栏的图框在一起（问"宇树春晚"裁出来却是隔壁的阿里上市图）。
  → 解法：左右半区都有图注时判为双栏，每个图注**只在自己那一栏内**找边界、算墨水、裁剪，并按栏内图形横向范围收紧 x，彻底隔离另一栏。
- **矢量表格陷阱**：有的"图"其实是矢量绘制的数据表，且与图注被大段正文隔开。这种**两侧都无成片图形**的情况直接**跳过**——宁可漏掉，也绝不产出夹着大段正文的脏图。

结果：120 份报告 5045 页抽出 **1960 张图**（raster 1565 / 矢量 395）。raster 图（产品照、流程图）裁得很干净；矢量图表偶有轻微多裁，异常版面被跳过。

### 3. 按需裁剪，不预生成图片

`figures.jsonl` 只存 `{source, page, caption, bbox}`，**不预渲染图片**。展示时 `/figure-image?source&page&bbox` 用 PyMuPDF `get_pixmap(clip=bbox)` 实时裁剪 + 磁盘缓存。好处：1960 张图不占磁盘，新增报告只追加元数据，bbox 调整无需重跑。

### 4. 放在哪：与"引用内联图表"互补

- **召回的图**是对**整个问题**最相关的图（未必对应某条 `[来源N]`）→ 放在回答末尾的"📊 相关图表（按问题召回）"区。
- 这与更早的"正文 `[来源N]` 引用到图表页 → 内联到引用段落正下方"是**两条互补路径**：前者答"这个问题有没有现成的图"，后者答"我引用的这条数据的原图"。

## 面试高频问题

**Q: 为什么不直接对每张图做 VL 描述再检索，要靠图注？**
A: 图注是作者写的图内容摘要，质量高且免费（已在文字层）。VL 重新描述 1960 张图有 API 成本和延迟，而图注检索已能精确命中（图6 case）。VL 描述可作为图注缺失时的兜底，属后续优化。

**Q: 裁剪不准怎么办？**
A: 分级处理：raster 图边界精确（占 80%）裁得干净；矢量/异常版面**宁可跳过**也不产脏图。前端每张图带图注+出处页码，点击可放大，用户可核对；加载失败（如无本地 PDF）自动隐藏。彻底方案是引入版面检测模型，属重型优化，当前启发式已覆盖主要场景。

**Q: 相关性阈值 0.55 怎么定的？**
A: bge-m3 归一化余弦，相关图注实测落在 0.6+，弱相关 0.4 上下。0.55 卡掉无关图、保留强相关，宁可少返也不返错图。可按召回率/准确率偏好调整。

**Q: 和 v0.5 的 chart 转写是什么关系？**
A: 正交互补。v0.5 让**图里的数字进文本索引**（回答里能引用图表数据）；v0.6 让**图本身能被召回并展示**（回答里能看到那张图）。v0.5 覆盖无文字层扫描页，v0.6 覆盖有文字层页上的插图。

# v0.5 图表多模态解析

> 一句话：把 v0.1 解析阶段记录在案的 **280个无文字层页面**（扫描图/纯图表页）用 Qwen-VL 转写为结构化文本入库（890块、零失败），研报图表里的数字从此可被检索问答。

## 为什么这一期重要

行业研报的核心数据大量长在图表里——市场规模曲线、融资统计柱状图、产业链图谱、SWOT矩阵。v0.1 的 PyMuPDF 只能提取文字层，这些页面被跳过意味着**知识库系统性缺失"数据最密集"的那部分内容**。

设计上的伏笔：v0.1 解析时就把空页页码记进了 `manifest.json` 的 `empty_pages`，这一期直接读清单干活，不用重扫120份PDF。**管道设计时给未来留接口，比将来重做便宜得多。**

## 技术方案

```
manifest.empty_pages → PyMuPDF渲染页面图(zoom=2, JPEG) → Qwen-VL转写 → JSONL逐页落盘
                                                                    ↓
            build_index 增量入库（kind=chart元数据）→ FAISS/BM25统一索引
```

### 1. VL模型选型：质量优先

DeepSeek 无视觉模型，对比两个候选后选了百炼 Qwen-VL：
- **Qwen2.5-VL 系列在文档/图表理解（ChartQA/DocVQA）属第一梯队**，"从图里精确抠数字"正是本期的核心需求
- 备选 GLM-4V-Flash 完全免费但是轻量档，密集图表漏提数据风险高
- 两家都是 OpenAI 兼容接口，实现做成 `VL_BASE_URL/VL_MODEL/VL_API_KEY` 三个配置项，**换供应商只改配置**——选型失误的代价被架构压到最低

### 2. 转写 Prompt 的设计

要求模型输出四类内容：页面标题与核心结论、每个图表的类型/坐标轴/全部数据点（年份+数值+单位）、表格逐行转文字、产业链图谱的环节与公司名。

两个实测迭代：
- 初版会输出"无表格展示"这类占位说明，污染索引——加一句"没有的板块直接跳过"解决
- `temperature=0.1`：转写任务要的是忠实，不是创造

### 3. 工程健壮性（280次外部API调用的现实）

- **逐页落盘 + 断点续跑**：每页成功立即 append 到 JSONL 并 flush，以 `(文档哈希, 页码)` 为幂等键。实际跑的时候进程在256页处被超时杀掉，重启后秒级续上，零重复调用
- **逐页重试**：单页3次指数退避，单页失败不中断整批
- **渲染也要保护**：有份PDF内部xref损坏，MuPDF渲染会报错——渲染和API调用分别包异常，坏页跳过记数
- 结果：280页全部成功，约消耗55万 VL tokens（免费额度内）

### 4. 统一索引：图表块是一等公民

转写文本走与正文完全相同的切块/编码/入库管道，唯一区别是元数据多了 `kind: "chart"`：
- 检索时图表块与文本块**同台竞争**——SWOT查询实测top5中4个图表块（rerank 0.99+）
- 生成的上下文标头加"（图表页转写）"，让LLM知道内容性质
- 前端来源卡片显示"· 图表页"标记，用户知道答案来自图表转写（转写可能有误差，提示用户必要时核对原图）

**没做成两套索引**（图表单独一个collection）：统一索引让上下游零改动，rerank自然处理两类内容的排序，没有发现需要分开的理由——不为"多模态"标签增加架构复杂度。

## 实测效果

- 索引规模：10,933 → **11,823块**（图表890块）
- "2024年具身智能融资情况"：召回量子位智库创投报告，给出173起/137亿元并标注口径差异
- "SWOT分析的优势劣势"：top5中4个图表块——这些内容在v0.4之前根本不在库里

## 面试高频问题

**Q: 为什么用VL转写成文本，而不是直接存图片向量（CLIP类多模态检索）？**
A: 取决于下游任务。问答场景最终要把证据塞给文本LLM生成答案，图片向量检索后还得过一次VL理解，等于把转写成本推迟到查询时（每次查询都付费+加延迟）。离线转写一次，查询时走纯文本链路，成本和延迟都更优。CLIP路线适合"以图搜图"类场景。

**Q: 转写错误怎么办？数字抠错了会污染答案。**
A: 三道缓解：选图表理解最强的模型而非最便宜的；上下文和前端都标记"图表页转写"，用户可溯源核对原图；评估集后续可加图表类问题监控质量。彻底方案是关键数字用OCR交叉校验，属于后续优化。

**Q: 280页一次性跑完，新增文档怎么办？**
A: 全管道幂等：parse_pdfs 记录新文档的 empty_pages → parse_charts 按 (哈希,页码) 跳过已完成 → build_index 按 chart:{哈希}:{页} 跳过已入库。新增PDF只处理增量。

**Q: 成本怎么控制？**
A: 渲染zoom=2平衡清晰度与token消耗；max_tokens=1500防失控输出；逐页落盘保证中断不浪费已付费的调用；图片base64直传避免OSS中转。280页约55万tokens，在免费额度内。
